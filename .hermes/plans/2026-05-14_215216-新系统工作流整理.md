# 森蓝ERP自动化 → 新系统工作流适配

## Goal
将当前森蓝ERP自动化工作流（V5.5）迁移到新系统上。用户可在 OpenClaw 或 Hermes 两种执行环境下运行。

---

## 必需 Skills（Hermes / OpenClaw 通用）

本项目正常运行需要加载以下 skills。新用户首次使用时，AI 需先确认这些 skills 全部可用：

| Skill | 用途 | 加载方式（Hermes） | 加载方式（OpenClaw） |
|-------|------|-------------------|---------------------|
| `senlan-erp-automation` | 主技能 — 全流程定义、踩坑速查、VXE操作、弹窗遮罩处理 | `skill_view(name="senlan-erp-automation")` | 内置 skill 自动加载 |
| `workflow-runner` | 在 OpenClaw 中注册为可重复执行的工作流 | 可选 | 必需（`workflow-runner` skill） |
| `openclaw-troubleshooting` | OpenClaw Gateway 故障排查（crash loop、飞书断连） | 不需要 | 运行前确认 gateway 正常 |
| `feishu-bypass-terminal` | 绕过飞书拦截 terminal 调用 | API/私聊模式必需 | — |
| `systematic-debugging` | 遇到 bug/失败时的标准排查流程 | 推荐加载 | 推荐加载 |
| `karpathy-coding-principles` | AI 编程准则 — 避免过度复杂、无关改动 | 开发新代码时加载 | — |

> **OpenClaw 用户注意**：启动前先检查 `openclaw-troubleshooting` skill 确保 gateway 在线。首次运行先 `workflow-runner` 注册工作流。

## 工作流总览（5步）

### Step 1 — 用户配置 API Key
用户需要提供：
- **阿里百炼 API Key**（视觉分析用，qwen-vl-plus / qwen3.6-plus）
- **DeepSeek / 大模型 API Key**（工艺推理、CNC编程用）

配置方式：
- 写入 `.env` 文件（`SILICONFLOW_API_KEY` / `DEEPSEEK_API_KEY` 等）
- 或通过 `llm_client.py` 的双 provider 路由管理

### Step 2 — 用户提供图纸路径
- 用户指定存放图纸文件的目录
- 图纸命名约定：`{生产单号}-{零件号}.pdf`（如 `C03026051501-001.pdf`）
- 单零件可省略零件号：`{生产单号}.pdf`
- 系统自动扫描目录，列出所有匹配的生产单号

### Step 3 — 模型通读项目代码，理解工作流
在执行之前，AI（无论 OpenClaw 还是 Hermes）需要先通读以下关键文件：

| 文件 | 作用 |
|------|------|
| `scripts/fill_by_vision.py` | 全流程入口，单/多零件调度 |
| `services/playwright_erp.py` | ERP页面交互（登录、搜索、表格填充） |
| `workflows/erp_process/process_reasoning.py` | 特征驱动推理引擎（五层读图逻辑） |
| `workflows/erp_process/prompts/vision_prompt.py` | 视觉分析提示词 |
| `services/llm_client.py` | 双 provider 路由 |
| `scripts/run_cnc_pipeline.py` | CNC 编程流水线 |
| `config/dropdown_options.py` | 49个工序选项映射 |
| `SETUP_GUIDE.md` | 环境配置指引 |
| `MEMORY.md` | 踩坑速查 |

阅读完成后 AI 应生成**执行计划摘要**给用户确认。

### Step 4 — 开始执行流程
执行分两步，必须顺序进行：

**① ERP填充**（`fill_by_vision.py`）：
```bash
cd ~/.hermes/senlan-automation
python3 scripts/fill_by_vision.py \
    --drawings-dir /path/to/drawings \
    --prod-no C03026051501 \
    --account 472
```
自动完成：视觉分析 → 保存分析缓存 `data/analysis_cache_{prod_no}.json` → 推理工序 → 填ERP → 保存

**② CNC编程**（`run_cnc_pipeline.py`）：
```bash
python3 scripts/run_cnc_pipeline.py --prod-no C03026051501
```
自动读取上一步保存的真实分析数据 → 编程Agent → 自审 → 交叉审查 → 保存 `data/cnc_pipeline_result.json`

⚠️ 两步必须顺序执行。禁止用硬编码假数据跑 CNC 管道。

### Step 5 — CNC 代码返回飞书
- CNC 编程结果（G代码）通过飞书 API 发送到用户私聊
- 消息格式：
  - 生产单号 + 零件号标识
  - 工序名称（数控精车 / 镜面放电）
  - G代码内容（Markdown 代码块）
  - 注意事项（刀具、转速、进给等）

## 执行环境适配

### Hermes 执行
- 直接在本会话中运行 `terminal()` 调用脚本
- 实时输出可见，可交互调试
- 推荐首次执行或需要调试时使用

### OpenClaw 执行
- 通过 `openclaw` 命令或 OpenClaw Gateway 调度
- 需要用 `workflow-runner` skill 注册为可重复执行的工作流
- 适合生产环境定时/按需执行
- 需确保 OpenClaw 环境中已安装 Playwright + 依赖

## 五层读图推理（工程师思维模型）

| 层级 | 内容 | AI实现方式 |
|------|------|-----------|
| 第一层 | 识别零件类型、材料、用途 | 读取标题栏，映射加工路线模板 |
| 第二层 | 提取几何特征 → 判断加工方式 | 视觉分析 + OCR，特征→工序映射规则 |
| 第三层 | 工序排序（先粗后精、热处理分水岭等） | 规则引擎 + 提示词约束 |
| 第四层 | 每道工序参数（刀具、转速、进给、余量） | LLM 调用切削参数知识库 + 工厂经验校准 |
| 第五层 | 特殊要求（利角、涂层、刻字等） | 识别图纸注释，自动加入工艺卡备注 |

---

## 工序排序固定逻辑

| 零件形状 | 默认工艺路线 |
|----------|------------|
| 方形/矩形 | 铣 → 磨 → 放电 |
| 圆形/回转体 | 车 → 磨 → 放电（或车→铣→磨→放电） |
| 异形 | 按特征组合推导 |

## Files 可能变更

- `.env` — API Key 配置
- `scripts/fill_by_vision.py` — 可能需适配新系统 ERP 页面结构
- `services/playwright_erp.py` — 登录/页面交互适配
- `workflows/erp_process/process_reasoning.py` — 工序规则调整
- `workflows/erp_process/prompts/vision_prompt.py` — 视觉提示词微调

## Risks & Tradeoffs

1. **新系统页面结构未知** — 当前 Playwright 选择器是针对森蓝 ERP 的，新系统需要重新适配
2. **视觉分析耗时** — 每张图 ~3min，N 张图 ≈ N×3min
3. **OpenClaw vs Hermes 执行差异** — OpenClaw 无交互终端，调试不如 Hermes 直观
4. **API Key 安全** — 不能硬编码，需要 `.env` 或环境变量管理
5. **CNC G代码准确性** — 依赖千问模型能力 + 审查环节把关
