# 森蓝ERP V3 — 多Agent + LLM提示词工程重构计划

## 目标
从 V2 的「单Agent + 硬编码prompt」升级为「主Agent调度 + 三个子Agent协作 + 完全提示词驱动」

## 当前问题 vs 改造方向

| 当前问题 | V3 改造 |
|----------|---------|
| 单 Agent 包办一切 | 主Agent调度 + 3个子Agent（识图/编程/审核） |
| prompt 散落在 Python f-string | Jinja2 独立管理 `templates/prompts/` |
| 无 system prompt | 每个 Agent 有独立的 system prompt 做行为约束 |
| CNC 代码 f-string 拼凑 | LLM 根据特征+设备+工艺生成完整 G 代码 |
| 无 few-shot | 视觉 prompt 加入图纸→JSON 样例对 |
| 无自我审查 | 编程Agent 自己审查代码合法性 |
| 无交叉审查 | 审核Agent 审查所有子Agent输出 |
| 无 LangChain 抽象 | PromptTemplate + Chain 模式 |

## Agent 详细设计

### 1. 识图Agent — `vision_agent.py`

**职责**：接收2D工程图 → 输出结构化零件信息

```
输入: {image_url, prod_no}
输出: {
  part_info: {name, material, hardness, shape, coating, qty},
  features: [{type, spec, qty, roughness, tolerance, note}],
  special_requirements: ["Sharp edge", "TiN coating"],
  confidence: 0.92,       # 自信度
  warnings: ["标注不清晰: 内孔公差"]
}
```

**System Prompt**（`prompts/vision/system.j2`）:
```
你是森蓝精密的高级工程图识别工程师。
你精通机械制图标准（ISO 8015、GB/T 1184），
能准确读取2D工程图中的标题栏、尺寸标注、公差带、粗糙度符号。

核心原则：
1. 读数准确：尺寸公差小数点后几位必须精确
2. 不遗漏：标注了粗糙度的面必须列出
3. 不懂的不猜：看不清的标注标明"模糊"
4. 识别利角：Sharp edge / 不倒角标注必须提取
```

**Few-shot 示例**（`prompts/vision/few_shot.j2`）:
```
示例1:
  图纸内容: Cutting Blade, K490 Vanadis 8, 58-63HRC
  输出:
  {
    "part_info": {"name": "Cutting Blade", "material": "K490 Vanadis 8", ...},
    "features": [
      {"type": "外形", "spec": "100×102×82mm"},
      {"type": "精孔", "spec": "∅10.47", "qty": 2, "tolerance": "H7", "roughness": 0.63},
      {"type": "利角", "note": "严禁倒角"}
    ],
    "special_requirements": ["Sharp edge", "TiN coating", "Laser marking: FMK-7736.030.61"]
  }
```

**内部架构**:
```python
class VisionAgent:
    system = Jinja2("prompts/vision/system.j2")
    prompt = Jinja2("prompts/vision/analyze.j2")
    few_shot = Jinja2("prompts/vision/few_shot.j2")

    def analyze(self, image_url: str) -> dict:
        messages = [
            {"role": "system", "content": self.system.render()},
            {"role": "user", "content": [
                {"type": "text", "text": self.prompt.render(few_shot=self.few_shot.render())},
                {"type": "image_url", "image_url": {"url": image_url}},
            ]}
        ]
        return self.llm.vision(messages, model="qwen3.6-plus")
```

### 2. 编程Agent — `cnc_agent.py`

**职责**：接收零件特征+工艺路线 → 生成各设备CNC代码 → 自我审查

```
输入: {part_info, features, process_plan, machine_types: ["TAKISAWA NEX-108", "SODICK AD32LS"]}
输出: {
  code_segments: [
    {machine: "TAKISAWA NEX-108", feature: "外形", code: "G90 G21\n..."},
    {machine: "SODICK AD32LS", feature: "精孔 ∅10H7", code: "C000\n..."}
  ],
  self_review: {           # 自我审查结果
    passed: true/false,
    issues: ["G00 安全高度不足"],
    suggestions: ["Z轴安全高度应≥50mm"]
  }
}
```

**System Prompt**（`prompts/cnc/system.j2`）:
```
你是森蓝精密的数控编程工程师，20年经验。
你精通 FANUC、三菱、海德汉等控制系统。
你生成的 G 代码可以直接上机运行，无需人工修改。

约束:
1. 安全第一：每个程序段必须有安全高度（G00 Z50）
2. 刀具补偿：精加工必须用 G41/G42 补偿
3. 转速进给：根据材料硬度匹配，K490(60HRC) 用低速
4. 冷却：所有切削段必须 M08
5. 格式规范：每行一个指令，注释用 ( )
```

**自我审查 Prompt**（`prompts/cnc/self_review.j2`）:
```
请审查你刚刚生成的 CNC 代码，逐项检查：

1. [安全] 是否有 G00 快速移动未设安全高度？
2. [刀具] 刀号是否正确？T0101 vs T0202？
3. [转速] S 值是否匹配材料硬度？{hardness}HRC → 合理转速？
4. [进给] F 值是否在合理范围？
5. [补偿] 精加工是否开启了刀具半径补偿 G41/G42？
6. [冷却] 是否每个切削段都有 M08？
7. [结尾] 是否有 M30 程序结束？
8. [坐标] G90/G91 是否与工艺要求一致？

逐项回答 yes/no + 理由，最后给 overall: pass/fail
```

### 3. 审核Agent — `review_agent.py`

**职责**：交叉审查识图Agent和编程Agent的输出

```
输入: {
  vision_output: {...},     # 识图Agent结果
  cnc_output: {...},        # 编程Agent结果  
  part_info: {...},         # 原始零件信息
}
输出: {
  vision_review: {
    passed: true/false,
    issues: ["特征遗漏: 3×M8螺纹孔未识别"],
    corrections: {...}      # 修正建议
  },
  cnc_review: {
    passed: true/false,
    issues: ["TAKISAWA代码缺少M08"],
    overall_score: 85/100
  },
  final_verdict: "approve" | "revision_needed" | "reject"
}
```

### 4. 主Agent — `supervisor.py`（重写）

**职责**：接收用户输入 → 分配任务给3个子Agent → 收集 → 最终审核

```python
class SupervisorAgent:
    def __init__(self):
        self.vision = VisionAgent()
        self.cnc = CNCProgramingAgent()
        self.review = ReviewAgent()

    def run(self, input_data) -> dict:
        # 1. 识图
        vision_result = self.vision.analyze(input_data["drawing_path"])
        
        # 2. 工艺推理（五层规则，同V2）
        process_plan = self._reason_process(vision_result)
        
        # 3. 编程
        cnc_result = self.cnc.generate(vision_result, process_plan)
        
        # 4. 如果自我审查失败 → 重试
        if not cnc_result["self_review"]["passed"]:
            cnc_result = self.cnc.generate(vision_result, process_plan, feedback=cnc_result["self_review"])
        
        # 5. 交叉审查
        review_result = self.review.check(vision_result, cnc_result)
        
        # 6. 如果审核不通过 → 循环修正
        max_retries = 3
        while review_result["final_verdict"] != "approve" and max_retries > 0:
            # 根据审核意见修正
            cnc_result = self.cnc.generate(vision_result, process_plan, feedback=review_result)
            review_result = self.review.check(vision_result, cnc_result)
            max_retries -= 1
        
        # 7. 最终合成
        return self._synthesize(vision_result, cnc_result, review_result)
```

## 图结构（V3）

```
graph.py:

login → detect_new_orders → fetch_feishu_drawing
  ↓ interrupt
supervisor_agent_run     ← 新：多Agent编排（非LangGraph节点，内部for循环）
  ├── 识图Agent.analyze()
  ├── 编程Agent.generate() + self_review
  ├── 审核Agent.check()   ← 循环直到approve或max_retries
  └── 主Agent.synthesize()
  ↓
erp_reconnect → fill_process_plan → fill_routing_cnc → END

中断点不变: fetch_feishu_drawing, generate_cnc
```

**关键变化**：`process_reasoning` 和 `generate_cnc` 两个 LangGraph 节点替换为**主Agent的for循环**，因为子Agent之间需要交互（审核→修正循环），不适合用静态图表示。

## 提示词模板渲染服务

```python
# services/prompt_service.py  ★新增
class PromptService:
    """统一提示词渲染入口"""
    
    def __init__(self, prompt_dir="templates/prompts"):
        self._env = Environment(loader=FileSystemLoader(prompt_dir))
    
    def render(self, path: str, **kwargs) -> str:
        """渲染提示词模板: render("vision/analyze", features=[...])"""
        return self._env.get_template(path).render(**kwargs)
    
    def render_messages(self, agent: str, **kwargs) -> list[dict]:
        """渲染完整 messages 列表（system + few_shot + user）"""
        system = self._env.get_template(f"{agent}/system.j2").render(**kwargs)
        user = self._env.get_template(f"{agent}/analyze.j2").render(**kwargs)
        return [
            {"role": "system", "content": system},
            {"role": "user", "content": user},
        ]
```

## 风险与待定

| 风险 | 说明 |
|------|------|
| LLM CNC 代码可能语法错误 | 靠 system prompt + self_review + 审核Agent 三重保障 |
| 循环修正可能无限 | `max_retries=3` 硬限制，超时回退到 f-string 模板 |
| 视觉分析准确率 | few-shot + system prompt 约束，但仍依赖模型能力 |
| 阿里百炼 qwen3.6-plus 的 G 代码能力 | 需实际测试，如果不行回退到 Jinja2 模板 + LLM 只填参数 |
