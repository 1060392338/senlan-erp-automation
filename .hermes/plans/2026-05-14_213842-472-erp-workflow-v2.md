# 森蓝ERP工作流 V2 — 去销售/飞书图纸驱动版

## 目标

去掉销售订单环节，改为纯粹的计划工艺驱动流程：
**飞书共享文档存图纸 → ERP检测新生产单 → 自动匹配图纸 → 工艺推理 → CNC编码 → 人工审核**

## 当前问题

V1 工作流依赖销售订单创建（`create_order`）作为入口，需要用户手动触发。用户要求改为：
1. 不再走销售订单
2. 飞书共享文档专门存放图纸，图纸文件名 = 生产单号
3. ERP 计划工艺模块的「发送时间」字段检测今天新生产单
4. 自动匹配飞书图纸 → 视觉分析 → 填写工艺 + 上传图纸到生产单 → CNC编码

## 新架构

```
Phase 1 (ERP检测 + 飞书拉图):
  login_erp → detect_new_orders → fetch_feishu_drawing
    ↓ interrupt_after (等待人工审核确认图纸匹配)
    
Phase 2 (离线AI推理):
  process_reasoning（内置视觉分析）→ generate_cnc
    ↓ interrupt_after (人工审核CNC代码)
    
Phase 3 (回填ERP + 结束):
  erp_reconnect → fill_process_plan（含上传图纸）→ fill_routing_cnc → END
```

| ❌ 删除 | `create_order` | 不再需要销售订单 |

| ❌ 删除 | `vision_analyze` | 视觉分析整合进 process_reasoning |

## 详细设计

### 1. 新建节点：`detect_new_orders`

**位置**: `workflows/erp_process/nodes/detect_new_orders.py`

**逻辑**:
1. 使用 `ctx.browser` 登录ERP
2. 导航到「计划管理 → 计划工艺」模块
3. 查找「发送时间」字段（输入框/表格列），获取今天的日期
4. 筛选出今天新增的生产单记录
5. 提取每个生产单的编号（prod_no）
6. 返回生产单列表到 state

**输入**: state (无特殊要求)
**输出**:
```python
{
    "new_orders": [
        {"prod_no": "PO20260514001", "send_time": "2026-05-14 10:30:00", "part_name": "Cutting Blade"},
        ...
    ],
    "pending_order_idx": 0,  # 当前处理的索引
    "checkpoint": Checkpoint.ORDERS_DETECTED
}
```

**UI 约束**:
- 森蓝ERP使用iframe嵌套，需先切换到iframe上下文
- 时间戳字段名可能是 `send_time` / `发送时间` / `create_time` 等，需试探性查找
- 使用 DrissionPage 的 `.eles()` 遍历查找

### 2. 重写节点：`fetch_feishu_drawing`（原 fetch_drawing）

**位置**: `workflows/erp_process/nodes/drawing_fetch.py`（重写）

**逻辑**:
1. 从 state 获取 `new_orders[0]`（当前待处理的生产单）
2. 访问飞书共享文档（用户提前创建好的文档空间）
3. 按生产单号 `prod_no` 查找匹配的图纸文件（文件名 = 生产单号）
4. 如果找到：
   - 下载图纸图片/PDF到本地缓存
   - 记录 `drawing_url`（飞书文件链接）和 `drawing_local_path`
5. 如果没找到 → 发送飞书消息通知用户缺少图纸
6. 中断等待人工确认

**输出**:
```python
{
    "drawing_url": "https://feishu.cn/...",
    "drawing_local_path": "/tmp/drawing_prod_no.jpg",
    "drawing_matched": True/False,
    "current_order": {"prod_no": "...", ...},
    "checkpoint": Checkpoint.DRAWING_FETCHED
}
```

**飞书文档集成**:
- 使用飞书开放平台 API（文档/云空间 API）访问共享文档
- 文件命名约定：`{prod_no}.jpg` / `{prod_no}.pdf`
- 需用户在飞书创建共享文档并授权 Bot 访问

### 3. 修改节点：`process_reasoning`

**位置**: `workflows/erp_process/nodes/process_reasoning.py`

**改动**:
1. 在 L2（几何特征提取）阶段，调用 `ctx.llm.vision()` 进行阿里百炼视觉分析
2. 删除独立的 `vision_analyze` 节点，视觉分析作为 process_reasoning 内部的子步骤
3. 从 `drawing_local_path` 读取图纸文件进行视觉分析
4. 原有5层推理逻辑不变（L1→L5）

**视觉分析整合后的伪代码**:
```python
# 在 process_reasoning 内部
if state.get("drawing_local_path"):
    # 调用阿里百炼 qwen3.6-plus
    vision_result = ctx.llm.vision(
        image_url=f"file://{drawing_local_path}",
        prompt=vision_prompt,
        model="qwen3.6-plus",
    )
    part_info, features = parse_vision_result(vision_result)
else:
    # 降级：从 input 获取默认信息
    part_info = state.get("part_info", default_part_info)
    features = state.get("features", default_features)
```

### 4. 修改节点：`generate_cnc`

**位置**: `workflows/erp_process/nodes/generate_cnc.py`

**改动**:
- 增强编码能力：根据「工艺路线 + 机床类型 + 不同特征模具」生成代码
- 不再只生成 TAKISAWA 和 SODICK 两段代码
- 改为按模具特征分段编码

**新逻辑**:
```python
for feature in features:
    machine_type = map_feature_to_machine(feature, process_plan)
    code_segment = generate_code_for_feature(feature, machine_type, part_info)
    cnc_segments.append(code_segment)

# 组装完整 CNC 代码
cnc_code = {
    "segments": cnc_segments,        # 分特征代码段
    "takisawa_nex108": ...,          # 保留原有（兼容）
    "sodick_ad32ls": ...,            # 保留原有（兼容）
    "feature_code_map": {            # 新：特征→代码映射
        "外形": "...",
        "精孔": "...",
        "螺纹": "...",
        "利角": "...",
    },
    "notes": notes,
}
```

**机床代码模板增强**:
- CNC 精车（TAKISAWA NEX-108）：增加原点设置、换刀指令、进给率
- 镜面放电（SODICK AD32LS）：增加电极参数、放电间隙、加工条件
- 每种特征映射到对应的 G 代码段

## 风险与待定

| 风险 | 缓解 |
|------|------|
| 飞书文档API权限 | Bot 需要 `drive:read` 权限 + 文档共享给 Bot |
| ERP 时间戳字段名不确定 | 需先手工登录看字段名，代码中留3种fallback |
| 多个新生产单 | 用 `pending_order_idx` 逐个处理，每次中断 |
| 图纸格式（PDF/JPG/PNG） | 视觉模型通常只支持图片，PDF需先转图片 |
| 飞书文件下载 | 飞书云空间API可能限制文件类型/大小 |

## 待确认

1. **飞书共享文档ID**：用户需提供一个固定的共享文档ID/URL，Bot才能访问
2. **时间戳字段名**：ERP 计划工艺模块的字段到底是"发送时间"还是其他名称？需登录确认
3. **图纸命名规范**：图纸文件命名 = 生产单号精确匹配还是模糊匹配（含前后缀）？
4. **CNC代码格式要求**：针对两种机床的不同特征，代码输出的具体格式要求
